Protéger les données confidentielles quand on utilise une IA

25 minGuide détaillé

Avant de coller un document, une liste de clients, un contrat, des notes RH ou du code propriétaire dans un service d’IA, il faut savoir ce qui est autorisé, quelles données sont réellement nécessaires et quels réglages de confidentialité s’appliquent.

Dans ce tutoriel
  • 1. Classer l’information avant de la transmettre
  • 2. Minimiser les données
  • 3. Respecter les règles de l’organisation
  • 4. Comprendre les contrôles de données de l’outil
  • 5. Utiliser une conversation temporaire n’efface pas toutes les obligations
  • 6. Ne jamais transmettre de secrets techniques
  • 7. Pour un document professionnel sensible

1. Classer l’information avant de la transmettre

Posez-vous trois questions : “Est-ce personnel ?”, “Est-ce confidentiel pour mon organisation ?”, “Est-ce nécessaire à la tâche ?”. Si la réponse à la troisième question est non, retirez l’information.

2. Minimiser les données

Remplacez les noms par des rôles, retirez les coordonnées, numéros de contrat, identifiants, secrets, mots de passe et données de santé ou RH si la tâche n’en dépend pas.

Au lieu de : “Mme Dupont, née le…, habite…” Utilisez : “Cliente A, 45 ans” uniquement si l’âge est réellement nécessaire.

3. Respecter les règles de l’organisation

Dans une entreprise, une école ou une administration, l’outil autorisé et le type de données permis peuvent être définis par une politique interne. Une fonction techniquement disponible n’est pas forcément autorisée pour des données professionnelles.

4. Comprendre les contrôles de données de l’outil

Pour ChatGPT, OpenAI documente des contrôles permettant notamment de gérer l’utilisation des conversations pour l’amélioration des modèles. Les options peuvent varier selon le type de compte et évoluer ; vérifiez la documentation actuelle avant de traiter des données sensibles.

Chemin exact : ChatGPT → profil → Paramètres → Contrôles des données

5. Utiliser une conversation temporaire n’efface pas toutes les obligations

Un mode temporaire peut modifier l’historique ou l’utilisation des données, mais il ne rend pas approprié le partage d’un secret professionnel, d’un mot de passe ou d’un document que vous n’avez pas le droit de transmettre.

6. Ne jamais transmettre de secrets techniques

  • Mots de passe.
  • Clés API.
  • Clés privées.
  • Codes de récupération MFA.
  • Jetons de session.
  • Secrets de configuration.

7. Pour un document professionnel sensible

Utilisez uniquement la solution validée par l’organisation, avec les paramètres et contrats adaptés. Si vous ne savez pas, demandez au responsable informatique, DPO ou RSSI avant l’envoi.

À retenir
La meilleure donnée sensible dans un prompt est souvent celle qu’on n’y met pas : minimisez, anonymisez et respectez l’outil autorisé.

Questions fréquentes

Anonymiser un nom suffit-il ?

Pas toujours. Une combinaison de fonction, date, lieu, projet et autres détails peut permettre de réidentifier une personne. Retirez tout ce qui n’est pas nécessaire.

Un abonnement professionnel autorise-t-il automatiquement toutes les données ?

Non. Les conditions techniques et contractuelles peuvent être meilleures, mais votre organisation doit toujours déterminer les usages autorisés et les catégories de données permises.

Puis-je coller une clé API pour demander de l’aide ?

Non. Une clé API est un secret d’authentification. Masquez-la ou remplacez-la par une valeur fictive avant de demander de l’aide.

Checklist de fin

  • ☐ Les données ont été minimisées
  • ☐ Les noms/identifiants inutiles ont été retirés
  • ☐ Aucun secret technique n’est présent
  • ☐ L’outil est autorisé par l’organisation
  • ☐ Les contrôles de données applicables sont connus
